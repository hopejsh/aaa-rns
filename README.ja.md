# AAA-RNS — AI エージェント研究ノート自動化システム

**サーバーもクラウドアカウントも Docker も情報システム担当者も要らない研究ノートシステム。**

展開してダブルクリックすれば動きます — LAN ケーブルを抜いたノート PC でもそのままです。
研究開発計画書や提案書といった**自社の文書をアップロードすると、その課題に合わせた研究
ノート体系を自動で構成**し、以後は実験日誌と測定データを入れるとノートを自動執筆します。
システムが書いたすべての文には根拠となった証拠番号が付き、証拠台帳が裏付けない主張が
残っているノートは確定できません。

한국어 · English · 日本語 を同等に扱います。

## クイックスタート

| 環境 | 方法 |
|---|---|
| macOS | `start_mac.command` をダブルクリック |
| Windows | `start_windows.bat` をダブルクリック |
| 共通 | `python3 server.py` → `http://localhost:8777` |

登録キー・アカウント・インストーラーは不要です。Chrome または Edge を推奨します（共有
フォルダモードが File System Access API を使用します）。前提は Python 3 だけで、macOS と
多くの Linux には既に入っています。

初回は 4 段階です: **文書のアップロード → 詳細分析 → 抽出結果の確認 → システムの生成。**
実際の文書がなくても、`sample_docs/` のサンプル計画書・指標表で試せます。

## 何が違うのか

**テンプレートではなく証拠から執筆します。** 実験日誌や測定 CSV をドラッグすると、ファイルが
SHA-256 ハッシュとともに添付され、内容から証拠が `[E#]` として登録され、実施内容・結果
データ・解釈が**その証拠だけで**作成されます。文はアップロードした原文からのみ生成され、
システムが事実を作り出すことはありません。

**拒否します。** 確定の前に決定論的なゲートが 4 つ実行されます。

| ゲート | 検査内容 |
|---|---|
| G1 証拠マッピング | 証拠番号のない文、存在しない証拠の引用、推測・誇張表現 |
| G2 過去整合性 | 確定ノートとの期間重複、同一指標の矛盾する数値、状態の逆行 |
| G3 数値・単位監査 | 合計・比率の再計算、単位表記、目標に対する方向、根拠のない「達成」表記 |
| G4 指針遵守 | 必須項目、引用証拠の原本添付 |

指摘が残っているノートは確定できません。ただし**何も破棄しません** — 本文と指摘の双方が
保存されるため、拒否は削除ではなく一つの記録です。

**確定は確定です。** 確定時、ノートのハッシュは**本文と署名の両方を覆い**、直前の確定ノートと
鎖状に連結されます。事後に本文を直すことはもちろん、承認者名をすり替えてもチェーン検証で
明らかになります。変更は改訂版（-R1、-R2 …）の発行でのみ可能で、原本と履歴の両方が残ります。

**外部依存 0 — 修辞ではありません。** PDF・DOCX・XLSX・HWPX・CSV のパーサー、DOCX/XLSX
生成器、チャート、ハッシュチェーンまで、すべてこのリポジトリ内に実装されています。CDN も
npm install もビルド段階もありません。CSP が外部送信そのものを遮断し、**例外は AI エンジン
3 社（Anthropic・Google・OpenAI）のエンドポイントのみ**です — 利用者が自ら接続した場合に
限り、既定はオフで、どの機能もこれを必要としません。

**26 の専門エージェント。** 7 階層・グループリード・typed packet・単一書き込み者ブラック
ボード（[agents/MAS_SPEC.md](agents/MAS_SPEC.md)）。プロンプトはエンジン中立のテンプレート
であり、決定論的コア（パーサー・ゲート・ハッシュチェーン）は LLM なしでブラウザ内で動きます。

## 率直な限界

後から気づくより先に記します。

- **LIMS ではありません。** 試料・在庫管理、装置連携、リアルタイム共同編集、モバイルアプリは
  ありません。
- **利用者の識別はローカルの PIN** であり、証明書ベースの認証ではありません。実際のアクセス
  統制は共有フォルダの OS 権限で行ってください。
- **時刻は端末の時計**であり、認定タイムスタンプ局のものではありません。
- **したがって、証明書ベースの電子署名や認定タイムスタンプを要求するいかなる制度も
  満たせません** — 一つの技術的事実が国ごとに別の名前で呼ばれているだけです:
  **ER/ES 指針**（日本・厚生労働省）、**21 CFR Part 11**（米国 FDA）、**eIDAS の適格電子署名・
  適格タイムスタンプ**と **EU GMP Annex 11**（EU）、そして**国家研究開発事業 研究ノート指針
  第7条 ①・②**（韓国）。規制記録システムではなく、研究公正性・再現性のためのツールです。
  脅威モデルは [SECURITY.md](SECURITY.md) を参照してください。
- ハッシュチェーンが証明するのは**内部整合性**です。チェーンの先端が記録保有者の管理外に
  固定されるまでは、改ざん**検出可能（tamper-evident）**であって改ざん不可能ではありません。

潤沢な資金があり、クラウドに抵抗がなく、配列・化学の深いツールが必要な研究室であれば
Benchling や Revvity の方が適しています。本製品は、それらが届かない研究室のためのものです。

## 検証

2 回のキャンペーン、**21 サイクル・計 2,446,015 回**のシミュレーション。引用の欠落・矛盾する
数値・改ざんされた署名・破損したバックアップ・偽造ライセンスを意図的に注入し、製品がそれらを
遮断することを検査しました。製品の実欠陥 5 件を発見・修正し、3 件はテストコード自体の欠陥と
判明したため実績に数えず撤回しました。

```bash
node simulation/run_simulation.mjs --campaign 2 --cycle 9 --iters 150000
```

シードに基づくため再現可能です。レポートは [`simulation/reports/`](simulation/reports/) にあり、
上書きによって**失われたキャンペーン 1 の 9 件のレポートを復元せずそのまま記した
[記録](simulation/reports/README.md)**が同梱されています。全文は
[検証報告書](docs/ja/verification-report.md)。

## エディション

このリポジトリのビルドは**コミュニティエディション**です — 登録キーがなく、プロジェクト数の
制限もありません。**エンタープライズエディション**は同じコードの
[`js/core/edition.js`](js/core/edition.js) の定数を一つ変えただけのもので、署名済みライセンス
キーを要求し、インストール 1 本をプロジェクト 1 つに紐付けます — 特定の会社・研究所へ発行する
配布本のための構成です。

ソースが公開されているため、キー検査はコードを書き換えられる人を止められません。この仕組みの
目的は技術的なコピー防止ではなく、発行先の確認です。

## データの置き場所

`data/` 課題構造・監査ログ · `notes/` 研究ノート · `notes_files/` アップロード原本 ·
`ledger/` 証拠台帳 · `archive/` 確定ノートの永久保管本。すべて利用者の端末、または指定した
チーム共有フォルダにのみ残り、いずれのフォルダも git は追跡しません。バックアップはファイル
ごとの SHA-256 マニフェストを含む ZIP 一つで、復元は全ファイルが検証を通過してはじめて
書き込みを開始します。
