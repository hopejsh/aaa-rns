대상에서 제외 + 시뮬레이션에 회귀 시험 추가.

### 2.5 부수 발견 (배포 구성 개선)

브라우저가 ES 모듈을 공격적으로 캐시하여 **프로그램 업데이트 후에도 구버전이
실행**되는 문제를 실브라우저 검증에서 재현. → 배포 서버(`server.py`)가
`Cache-Control: no-store` 를 강제하도록 구성 (기존 AAA-RNS server.ps1 과 동일 정책).

### 2.6 사이클 11 — 다국어 검증 규칙 정밀화 (하네스 수정, 제품 무결)

영어·일본어 지원을 추가하며 `i18n_dictionary` 카테고리를 신설했다. 첫 실행에서
13종이 적발되었으나 전수 확인 결과 **모두 검증 규칙의 오탐**이었고, 번역은 정확했다:

- **숫자 소실 오탐**: "월 1회 알림" → "Monthly reminder" 처럼 `1` 이 영어의
  monthly·single·a 로 자연 흡수되는 것은 올바른 번역 → `1` 을 계약에서 제외.
- **월 이름 오탐**: "7월 12일" → "On July 12" 는 정확한 현지화 →
  `N월` 이 영어 월 이름으로 옮겨진 경우를 인정하도록 규칙 보강.
- **길이 오탐**: 한→영 확장률(통상 2~3.5배)을 감안해 상한을 5배로 완화.
- **한글 잔존 오탐**: 언어 선택기의 3개 언어 병기, 한국식 수 표현 설명(억·천만),
  한글 파일명 경로는 의도된 유지 → 허용 목록에 등재.

규칙 정밀화 후 재실행에서 무결함 통과했다. 제품 결함 아님.

## C2.1 확정 해시가 서명을 덮지 않음 (심각도: 높음)

**증상.** 확정(sealed)된 노트의 최종 승인자 이름을 사후에 바꿔도 무결성 검사와
해시 체인 검증 어느 쪽에서도 탐지되지 않았다 (사이클 5, 1,045회 재현).

**원인.** `seal_hash = SHA-256(본문해시 + 직전해시)` 로 계산되어 **서명 블록이
봉인 범위 밖**이었다 (`js/core/notes.js` sealNote). 본문은 보호되지만 "누가
승인했는가"는 보호되지 않아, 감사 대응 시스템의 부인방지(non-repudiation)에
공백이 생긴다.

**해결책 도출.** 세 안을 비교했다. ① 서명 다이제스트를 별도 필드로 저장 후 검사 —
필드 자체를 함께 위조하면 무력. ② 해시 공식을 바꾸되 무버전 적용 — 기존 확정
노트가 전부 "손상"으로 표시되어 거짓 경보가 신뢰를 파괴. ③ **공식을 바꾸되
버전 태그로 구분** — 채택. 새 노트는 `seal_algo:'v2'` 로
`SHA-256(본문해시 + 서명다이제스트 + 직전해시)` 를 쓰고, 기존 v1 노트는 원래
공식으로 검증한다. 검증 시 저장된 다이제스트를 신뢰하지 않고 **실제 서명에서
재계산**하므로 필드 위조도 통하지 않는다.

**검증.** 서명자 변조 시 무결성 검사와 체인 검증 양쪽에서 탐지 확인, 사이클 6~9
에서 사후 변조 5종(본문·측정·서명자·해시·기간) 전량 탐지.

## C2.2 자유 서술의 거짓 달성 주장을 놓침 (심각도: 중간)

**증상.** 목표 미달 측정값에 측정조건을 "목표 달성" 으로 적으면 G3 를 통과했다
(사이클 5, 1,012회 재현).

**원인.** G3 의 달성 표기 검사가 구조화된 `achieved` 플래그만 보고 자유 서술
필드는 보지 않았다 (`js/core/gates.js`). 그러나 감사자에게는 두 표기가 동등하게
오도적이며, 실제 연구자는 자유 서술로 적는 경우가 더 많다.

**해결책 도출.** 자유 서술까지 검사 범위를 넓히되, 거짓 양성이 더 해롭다는 점을
반영했다. "미달성/未達成/not achieved" 같은 **부정 표현을 먼저 제외**한 뒤 달성
주장으로 판정하며, 한국어·영어·일본어 표현을 모두 인식한다(기록이 3개 언어로
생성되므로).

**검증.** 3개 언어 거짓 주장 전량 차단, 부정 표현·중립 표현은 오탐 0 확인.

## 시험 코드 결함 3건 (제품 무결 — 거짓 양성)

발견된 8종 중 3종은 시험 코드 자체의 결함이었고, 재현을 통해 제품 무결을 확인한
뒤 시험을 수정했다: ① `verifySealChain` 은 async 인데 `await` 없이 호출(2곳),
② 라이선스 변조 시험이 "같은 문자로 치환"될 수 있어 실제 변조가 일어나지 않음.
**거짓 양성을 제품 수정으로 오처리하지 않은 것이 이 캠페인의 핵심 규율이다.**

## C2.3 조건부 팝업 미번역 (사용자 보고 · 심각도: 중간)

**증상.** 일본어 모드에서 기간이 맞지 않는 파일을 올리면 안내 모달의 제목·본문·
버튼이 한국어로 나왔다 (사용자 스크린샷).

**원인 (두 겹).** ① 이 모달은 *날짜가 노트 기간 밖일 때만* 뜨는 조건부 팝업이라
런타임 스캔이 한 번도 띄우지 못했다 — 실행 기반 검증의 사각지대. ② 소스 정적
추출기는 `icon('zap') + '라벨'` 같은 **문자열 연결 표현식**을 읽지 못해 버튼
라벨을 놓쳤다.

**해결책.** 검증 도구를 두 축으로 보강했다. 모달·토스트 문구를 AST 로 전수
추출하되(조건부 팝업도 소스에는 존재하므로 실행 없이 잡힌다), 추출기가
BinaryExpression·ConditionalExpression 연결까지 해석하도록 확장했다. 이 도구가
찾아낸 **미번역 104건**(모달 제목·본문·버튼·토스트·placeholder)을 전량 번역했다.

**검증.** 문제의 모달을 의도적으로 재현(다른 스프린트 노트에 파일 업로드)해
일본어·영어 모두 제목·본문·목록·버튼이 완전 번역됨을 확인. 사이클 9(149,999회)
회귀 무결함, 런타임 스캔 UI 누락 0건 유지.
