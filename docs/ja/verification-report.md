## 1. なぜシミュレーションか

研究ノートシステムが信頼されるのは、**記録を拒む**ふるまいゆえです。正常系だけを試しても
それは証明できません。そこで各サイクルでは、引用の欠落・矛盾する数値・改ざんされた署名・
破損したバックアップ・偽造ライセンスなどの欠陥を意図的に注入し、製品がそれらを遮断すること
を検査します。何も見つからないサイクルは、それ自体が成功ではありません — シナリオをより
過酷にしたうえで初めて意味を持ちます。

## 3. 発見・修正された製品の実欠陥

### 3.1 確定ハッシュが署名を覆っていなかった（重大度: 高）

**症状.** 確定（sealed）したノートの最終承認者名を後から変更しても、完全性検査でもハッシュ
チェーン検証でも検出されませんでした（サイクル 5 で 1,045 回再現）。

**原因.** ハッシュが `seal_hash = SHA-256(本文ハッシュ + 直前ハッシュ)` で計算され、**署名
ブロックが封印の範囲外**でした（`js/core/notes.js` sealNote）。本文は保護されるものの「誰が
承認したか」は保護されず、監査対応システムとしての否認防止に空白が生じていました。

**解決策の選定.** 三案を比較しました。① 署名ダイジェストを別項目に保存して検査する — 項目
ごと偽造されれば無力。② ハッシュ式をそのまま変更する — 既存の確定ノートがすべて「破損」と
表示され、誤警報が警報そのものへの信頼を壊します。③ **式を変更したうえでバージョンで区別
する** — これを採用。新しいノートは `seal_algo:'v2'` として
`SHA-256(本文ハッシュ + 署名ダイジェスト + 直前ハッシュ)` を用い、既存の v1 ノートは元の式で
検証します。検証時は保存されたダイジェストを信頼せず**実際の署名から再計算**するため、項目の
偽造も通用しません。

**検証.** 署名の改ざんは完全性検査とチェーン検証の双方で検出されるようになり、サイクル 6〜9 で
改ざん 5 種（本文・測定・署名者・ハッシュ・期間）をすべて検出しました。

### 3.2 自由記述による虚偽の達成主張を見逃していた（重大度: 中）

**症状.** 目標未達の測定値に対し、測定条件へ「目標達成」と記述すると G3 を通過していました
（サイクル 5 で 1,012 回再現）。

**原因.** G3 の達成表記の検査が、構造化された `achieved` 項目のみを見て自由記述を見ていません
でした（`js/core/gates.js`）。しかし監査者にとって両者は等しく誤解を招くものであり、実務では
自由記述で書かれる場合の方が多いのが実情です。

**解決策の選定.** 検査範囲を自由記述にも広げつつ、誤検出（偽陽性）の方が有害であるという前提を
置きました。「未達成」「not achieved」などの否定表現を先に除外したうえで達成主張と判定し、記録が
3 言語で生成されることから、韓国語・英語・日本語の表現をいずれも認識します。

**検証.** 3 言語すべてで虚偽の主張を遮断し、否定表現・中立表現での誤検出はゼロでした。

## 4. テストコードの欠陥 3 件（製品は健全 — 偽陽性）

表面化した 8 系統のうち 3 系統はテストコード自体の欠陥でした。いずれも再現して製品が健全である
ことを確認したうえで、テストを修正しています: `verifySealChain` は async であるのに `await` を
付けずに呼び出していた（2 か所）、ライセンス変異試験が同じ文字への置換を許してしまいキーが実際
には変わらなかった、というものです。**偽陽性を製品修正として扱わないことが、本キャンペーンの
中心的な規律です。**

## 5. 多言語の検証

全画面・全ダイアログを英語と日本語で自動的に操作しながら、翻訳層が解決できなかった文言を収集
しました。3 つの死角が見つかり、いずれも解消しています。

- 特定のデータ状態でのみ現れる条件付きダイアログは、実行ベースの走査では一度も表示されません
  でした → モーダルの文言をソースからも静的に抽出するようにしました。
- 静的抽出器が `icon('zap') + 'ラベル'` のような連結表現を読めませんでした → 二項式・条件式も
  解釈するよう拡張しました。
- DOM 翻訳器が**確定済みの記録本文**まで書き換えていました（例: 「목표 63%」→「target 63%」）。
  これでは表示されるノートが封印されたハッシュと食い違います → 正本文書を翻訳対象から除外し、
  ラベルは文書用辞書から取り、システムが作文する文は執筆時点で選択言語により生成する方式に
  改めました。

最終状態: **UI の未翻訳 0 件、半端な翻訳 0 件。** 韓国語のまま残るのは会社データ（課題名・氏名・
引用された証拠）であり、これらは翻訳してはならないものです。
